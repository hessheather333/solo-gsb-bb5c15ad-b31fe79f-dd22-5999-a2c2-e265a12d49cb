# 🎙️ 无线麦克风频率协调器

面向**现场音频工程师**的无线麦克风频率协调 Web 应用。录入最多 8 台设备的名称、工作频率与保护间隔、可锁定频道；系统枚举任意两台不同频道产生的互调产物，标出落入任一频道保护区的冲突及其来源，并能在指定频段 / 步进 / 最大偏移内自动协调出**总偏移最小**的无冲突方案。

技术栈：**Node.js + Express + SQLite（better-sqlite3）+ 原生 HTML/CSS/JavaScript 前端**（无构建步骤、无前端框架）。

---

## 🚀 一条命令初始化并启动

### 方式一：Docker Compose（推荐）

```bash
docker compose up --build -d
```

首次会自动构建镜像、初始化 SQLite 数据库并启动服务。打开浏览器访问：

> **http://localhost:3000**

停止：`docker compose down`（数据保留在命名卷 `coordinator-data` 中）；删除数据：`docker compose down -v`。

### 方式二：本地 Node.js（需 Node ≥ 20）

```bash
npm install && npm start
```

服务同样监听 **http://localhost:3000**（SQLite 文件位于 `./data/coordinator.db`，首次启动自动建库建表）。

## 📻 互调模型

对任意两个**不同**频道 `f1`、`f2`，枚举以下互调产物：

| 类型 | 表达式 |
| --- | --- |
| 二阶差频 | `|f1 − f2|` |
| 二阶和频 | `f1 + f2` |
| 三阶互调（两个方向） | `|2f1 − f2|`、`|2f2 − f1|` |
| 载波保护带重叠 | `|f1 − f2| ≤ g1/2 + g2/2` |

每个频道的保护区为闭区间 **`[f − g/2, f + g/2]**（g 为该频道的保护间隔）。只要某一互调产物落入**任一**频道保护区，即报告一条冲突，并给出：

- 冲突类型与产物频率；
- **来源频道对**（产生该互调的两台设备）；
- **受害者频道**（被命中的设备）及与载波中心的频偏。

> 注意：三阶互调是**三通道**约束——`f1`、`f2` 产生的 `2f1−f2` 往往命中**第三台**设备。例如三台等间隔的话筒 510.0 / 510.2 / 510.4 MHz：`2×510.2 − 510.4 = 510.0` 正好命中第一台。本工具完整枚举此类冲突。

## 🧠 自动协调规则

- **频段** `[bandStart, bandEnd]`、**步进**（如 25 kHz）、**最大偏移**均由用户指定；候选频率为频段内与步进对齐的频点栅格。
- **锁定的频道保持不动**；仅调整未锁定频道，且每台的 `|新频率 − 原频率| ≤ 最大偏移`。
- 搜索采用 DFS + MRV（最少候选优先）+ 前向检查 + 动态下界剪枝 + 记忆化，目标为：
  1. **总偏移 `Σ|fᵢ − fᵢ⁰|` 最小**；
  2. 总偏移相同（同分）时，**按录入顺序**逐频道选择**更低**频率（字典序最小）。
- 最优性经搜索完整证明时标记为严格最优；结果始终经过独立复核，保证残余冲突为 0。
- **无解时所有频道保持原值**，并给出具体原因：
  - 锁定频道之间本身存在不可消除的冲突；
  - 某台设备在频段 / 步进 / 最大偏移内没有可用频点；
  - 或可证明在全部约束下不存在无冲突方案。
- 极端组合空间（如 8 台设备、极宽频段、极小步进）触及 500 万搜索节点上限时，会返回**已验证零冲突的最佳已知方案**并明确标注“未完成最优性证明”，建议缩小频段 / 最大偏移后重试。

## 💾 方案保存

点击「保存方案」会按当前设备与参数重新计算一次协调结果，并连同名称、备注、频段参数、每台设备的原频率 / 协调频率 / 锁定状态 / 偏移一起写入 SQLite。可在页面下方**载入**或**删除**历史方案。

## 🔌 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/analyze` | 仅枚举当前频道的互调冲突 |
| POST | `/api/coordinate` | 自动协调（不保存） |
| POST | `/api/plans` | 协调并保存方案 |
| GET | `/api/plans` | 方案列表 |
| GET | `/api/plans/:id` | 方案详情 |
| DELETE | `/api/plans/:id` | 删除方案 |

`/api/coordinate` 请求示例：

```json
{
  "channels": [
    { "name": "Mic-A", "frequencyMHz": 510.0, "guardKhz": 100, "locked": false },
    { "name": "Mic-B", "frequencyMHz": 510.2, "guardKhz": 100, "locked": true }
  ],
  "options": { "bandStart": 509.0, "bandEnd": 511.0, "stepKhz": 25, "maxShiftKhz": 1000 }
}
```

## 📝 使用提示（现场实践）

- 保护间隔建议取接收机实际频道间距需求（常用 100–300 kHz，依设备型号而定）。
- UHF 系统常见 25 kHz / 50 kHz 步进；协调前先在接收机手册中确认可用频段与步进。
- 先把已占用、不能移动的主频道**锁定**，再对其余话筒执行协调。
- 协调完成后请仍以现场扫频 / 监听为准——本工具解决设备间的互调自扰，不感知外部射频环境（电视台、对讲机等）。
